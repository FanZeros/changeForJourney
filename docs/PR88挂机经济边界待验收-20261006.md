## 一、需要独立决定的经济规则

### 1. 超过五名英雄的经验池

`ExpTable.partyExpMult` 现有五档为 `1 / 1.5 / 2 / 2.5 / 3`。旧 getter 在六人以上数组越界回到一倍；PR #88 将人数取整并钳制到最高三倍。

这会使六至十二名有效英雄的账户英雄经验池由 `B` 变成 `3B`，是实际产出变化，不能只称修接口。三倍是总池，不是每名英雄都拿三倍，也不是每队再发一份三倍。

推荐待讨论方案：保留五档，六至十二人沿用最高三倍；金币、账户远征经验、击杀率、装备／卷轴掉落不按队数倍增。本轮不实施。

验收须分开：0–12人数、非整数／无效输入、已锁队、重复英雄、空槽、旧人数快照、领取时换队。实际在线击杀按本队存活领取者发奖，不能以账户离线计算 API 代替在线链证明。

### 2. 收益锚点属于账户还是队一

旧逻辑受到队一 `currentStageId` 与 `battleMode` 影响。PR #88 改为账户 `maxStageId`：普通最高关有严格 `true` 首通证据用本关，无证据用合法前驱；难度首关回上一难度末关，终焉取同难度普通末关。

该方案将选关与账户收入解耦，但部分旧档会上升、部分会下降，不能声称收益不变。

固定源码反例：

| 输入 | 旧收入锚 | PR #88 收入锚 |
|---|---|---|
| max=1005，current=101，空账本，firstClear | 101 | 1004 |
| 同上，mode=offline | 1005 | 1004 |
| max=1005，current=101，1005严格已通，firstClear | 101 | 1005 |
| max=current=2401，空账本 | 2401 | 2305 |
| max=current=999，空账本 | 数值回退约905 | 同难度末关2305 |
| max=current=1999，空账本 | 数值回退约1905 | 同难度末关4605 |

推荐待讨论方案：账户最高锚点与队一解耦，严格证据决定本关／前驱；不普遍补偿、不根据当前模式伪造最高首通。本轮不实施。

### 3. 掉落是否包括已通最高普通关

PR #88 仍保留排除式遍历：最高105且已通时，收入可用105，掉落混合104、103、102、101，不含105。终焉使用下一难度首关作为内部排除边界，得到本难度末章五关；这不解锁下一难度或使用下一难度收益。

推荐暂保留原排除式契约；改为包含式需单独授权、概率与种子关号红绿测试。本轮不实施。

### 4. 扫荡收入与装备锚不同

当前 `SweepService` 的装备取 `sweepStageId`，金币／经验基数仍取 `IdleIncomeConfig.get(maxStageId)`。最高1005未通时，装备可能来自1004而收入仍按1005；终焉的扫荡前驱还有跨难度差异。

这是既有邻接问题，不能因为 PR #88 修改 OfflineCalc 就宣称扫荡同时修好。本轮记录，不擅改。

## 二、不应作为平衡争议搁置的一致性错误

这些修复不新增经济档位或奖励：

1. 永久首通只接受数字／字符串键严格 `true`；普通恢复的空、缺省或 `false` 不能撤销已经确认的本地事实。保留 PR #91 并集，不整块覆盖成 PR #88 的全量替换。
2. 终焉按真实关链排序，不能以原始 ID 的 `math.max` 合并共享进度。`3999` 实际在地狱末关9205之后；旧队追赶困难4605、目的地4701，不得把账户最高3999降成4701。
3. 存档规范化与实时镜像区分：读档可按既有规则退出终焉，实时镜像不能回灌重建战斗；快照异常要返回失败，不先消费变化后静默丢失。
4. RCH 免疫／限时状态按宿主持有，重开某队或开关塔不能清默认场景／其他队状态；正常、嵌套及异常出口都恢复原挂载。
5. 养成回执与数据推送幂等，不能调用不存在的 API、不能把同布局养成伪装编队重开，也不能中断 ETS 已消费死亡事件后的成长提交。
