# 协作者画像与协作偏好

## 基础

- 沟通风格：极简短指令（常 5–20 字），期望 AI 自行调研、给方案、快速落地；不喜欢被反复追问。
- 语言：简体中文。用户可能有笔误（如"例会"=立绘、"该名字"=改名字），按语境理解。
- 技术背景：熟悉游戏产品与网络梗文化，不深入引擎技术细节，依赖 AI 处理实现。

## 协作规则

- **不自行取消或退出任务**；每次完成或受阻都先简报结果，再调用 `AskUserQuestion` 以选项询问下一步并等待选择，禁止纯文字结束。
- 每次完成后只 push 本轮授权的分支；推送前核对实际 Git 分支，不推其他分支、不强推。
- 凭据（PAT 等）不写入仓库、配置、日志或记忆；临时认证用后即清理并提示撤销。

## 工作特征

- 决策风格：快速试错——"先简单试试""A 先试试"，小步验证后再全量。
- 验收标准高且直接：逐张看图反馈，直接否定是常态，快速归因给修正方案即可。
- 风险意识：主动规避真实名字（如闪电麦昆→闪电卖鸡），提醒"不建议直接上"时接受替代方案。
- 偏好玩梗浓度高的文案与形象。
- 反馈载体：直接上传游戏内截图到 `_uploads/` 或用图说明。
- 资源可能伪装扩展名上传（如 `.mp4` 实为 ZIP 音效包），按文件头识别。
- 工作模式：多会话并行同一项目，会引用另一会话的产出要求落地。

## 反复出现的模式

- "图像晚点搞"往往很快变成当前需求，提前留好图像管线。
- 会临时插入新需求打断当前任务；挂起的任务要做好标记。
