# persona.md — 用户画像(三层)

## 基础画像

- 称呼:用户未设置特定称呼(直呼需求);助手默认自称"我"
- 唤醒词:未设置(wake_word=null,用户可随时说"改唤醒词"补设)
- 沟通风格:极简短指令(常 5-20 字),期望 AI 自行调研、给方案、快速落地;不喜欢被反问太多
- 语言:简体中文;用户有笔误习惯("例会"=立绘、"该名字"=改名字),按语境理解

## 工作特征

- [confirmed] 不自行取消或退出任务；每次交付后必须调用 AskUserQuestion，以选项询问下一步，禁止纯文字结束。遇阻碍也给可行选项，不擅自停工；尊重用户后续停止指令。
- [confirmed] 每次完成后提交并只 push 本轮授权的当前功能分支；推送前核对实际 Git 分支，不推其他分支、不强推。旧交接中的分支名不覆盖用户最新指令。

- [observed] 决策风格:快速试错——"先简单试试""先试试""A 先试试",小步验证后再全量(计数:3)
- [observed] 验收标准高且直接:逐张看图反馈,"都不太行""无法验收通过"这类直接否定是常态,勿玻璃心,快速归因给修正方案(计数:3)
- [observed] 风险意识:主动要求"避开真实名字"(闪电麦昆→闪电卖鸡)、提醒"不建议直接上"会接受替代方案(计数:2)
- [observed] 喜欢玩梗浓度拉满的文案与形象;接受"发色不锁"等自由度换梗味(计数:2)
- [observed] 工作模式:**多 agent 会话并行同一项目**(重要,见 antibodies);会引用另一会话的产出(文案/文档)让本会话落地(计数:2)
- [observed] 反馈载体:直接上传游戏内截图到 /workspace/_uploads/ 或粘贴会话截图,用图说话
- [observed] 资源会伪装扩展名上传(如 se.mp4 实为 ZIP 音效包)，按文件头识别不要被后缀骗(计数:1)
- 反馈偏好:直接批评型,给修正要点而不是情绪安慰
- 技术背景:懂游戏产品/梗文化,不深入引擎技术;依赖 agent 处理技术细节
