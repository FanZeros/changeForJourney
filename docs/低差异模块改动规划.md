# 低差异模块改动规划

> 整理日期：2026-09-25。来源：用 `tempGame/skills/source-similarity` 把终焉之门
> 与同源已发布版本（镜像 856061 / `p_u1jd`）做内容级比对，筛出「同路径且相似度 ≥ 90%」
> 的模块。这些是从原版原样搬过来、几乎没改过的部分，是后续差异化改造的候选面。
>
> 状态：第 1 批已完成（2026-09-25，提交 `ac91aed`，已推送 `feat925/clean`）。
> 分支基线 `feat925/clean`。

## 0. 比对结论（为什么是这些）

- 同路径文件 109 个，加权相似度 77.6%；其中 **65 个 ≥ 90%**，覆盖约 17800 行。
- 对称相似度只有 18%，主因是**目录重构**而非内容改写：发布侧的 `server/` 在终焉之门
  是 `rules/`，`network/Client.lua`、`network/Server.lua` 联网壳已删除，`ui/` 拆成了
  `ui/battle/`、`ui/character/` 等子目录。所以「低差异」只在同路径可比的模块上有意义。
- 按目录：`shared/` 85.3% 的同路径文件 ≥ 90%，`systems/` 74.1%，`config/` 只有 31%
  （关卡配置全家桶已被统一改过，约 40%）。

## 1. 必须处理（死代码，改动零风险）—— 已完成

已在 `ac91aed` 删除，dist 已确认不含这些模块。`ui/relic/` 现在只剩 `RelicReforgePanel.lua`。

这些文件相似度高是因为**根本没人调用**，不是因为设计稳定。

| 模块 | 相似度 | 现状 | 动作 |
|---|---|---|---|
| `systems/RelicGrid.lua`（432 行） | 99.8% | 旧的 10×8 俄罗斯方块式摆放。现行遗物是祭位模型（`RelicService.PlaceOnGrid` 用 `slotId`），全仓无 `require` | 已删除 |
| `ui/relic/RelicPanel.lua`（697 行） | — | 旧总面板，只在 `ModuleMap` 注册，无任何 UI 入口打开 | 已删除 |
| `ui/relic/RelicBagPanel.lua`（679 行） | — | 只被 `RelicPanel` 引用 | 已删除 |
| `ui/relic/RelicDetailPanel.lua`（564 行） | — | 只被上面两个引用 | 已删除 |

保留 `ui/relic/RelicReforgePanel.lua`：它由 `runtime/ClientMessageHandler.lua` 直接调用，是活的。

实际清理 2372 行加 5 张格子大图 `ICON_YW_*`，不改变重铸、祭位、属性结算。

`RelicDefs` 同步去掉了 `cells`、`iconGrid`、`getTypeCells`，以及只服务旧网格的

## 2. 建议改造（玩家能感知，且是原样搬运）

按「改动能不能被玩家看见」排序。

### 2.1 战斗手感与数值 —— 优先

这些直接决定打起来的感觉，目前与原版几乎一致。

| 模块 | 相似度 | 职责 | 改造方向 |
|---|---|---|---|
| `shared/battle/DamageFormula.lua` | 100% | 伤害公式 | 暗黑向：加入暴击溢伤、元素抗性、精英惩戒等终焉之门专属项 |
| `systems/CombatFormula.lua` | 99.0% | 战斗结算入口 | 配合公式改造，接入新的伤害乘区 |
| `systems/UnitAttributes.lua` | 99.3% | 单位属性汇总 | 新增终焉之门属性维度（如终焉抗性） |
| `systems/AttributeDef.lua` | 95.1% | 属性定义 | 同上，补属性枚举与显示名 |
| `systems/DropSystem.lua` | 99.1% | 掉落 | 掉落表差异化，绑定终焉之门的稀有度与套装权重 |
| `config/IdleIncomeConfig.lua` | 99.9% | 挂机收益 | 收益曲线按远征等级重做，与现有离线收益弹窗对齐 |

## 3. 明确不动

这些高相似是因为它们本来就是通用基础设施，改了只有风险没有收益。

- `systems/EventBus.lua`、`systems/GameEvents.lua`：事件总线。
- `core/Viewport.lua`、`core/BattleLayout.lua`、`core/UiToast.lua`：布局与提示基础件。
- `nvg_overrides.d.lua`：LSP 类型声明。
- `shared/*/` 下的 `*Schema.lua`（`BattleSchema`、`ProfileSchema`、`EquipmentSchema`、
  `SigninSchema`、`DungeonSchema`、`CurrencySchema`、`TaskSchema`、`TalentsSchema`、
  `SessionSchema`、`TavernSchema`、`RelicSchema`、`RedeemSchema`、`QuotaSchema`、
  `SlotEnhanceSchema`、`PlayerSchema`）：存档结构。改字段会破坏旧档兼容。
- `systems/ArtifactBridge.lua`、`systems/TutorialManager.lua`、`systems/ButtonFeedback.lua`、
  `systems/GameBGM.lua`、`systems/GameSFX.lua`：桥接与表现层，相似度 95%~99%，功能正常。

## 5. 建议执行顺序

1. **第 1 批（清理）**：已完成，见 §1。
2. **第 2 批（战斗差异化）**：`DamageFormula` → `CombatFormula` → `UnitAttributes` /
   `AttributeDef`，一条链改完再验证战斗数值。
3. **第 3 批（经济）**：`IdleIncomeConfig` + `OfflineCalc` + `DropSystem`，对齐远征等级曲线。
4. 神器、装备模板、抽卡逻辑等玩家暂时无感的，等有具体玩法需求再动。

每批单独提交到 `feat925/clean`，不混入功能改动。
