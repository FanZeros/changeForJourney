# 护盾成长层设计（Shield Scaling）

> 实装于 `scripts/systems/AttributeDef.lua`（`AD.SHIELD_SCALING` 配置）+ `scripts/systems/UnitAttributes.lua`（`recalc()` 成长层）。
> 当前档位：`hpRatio=8%` / `derivedLevelFactor=5%` / `enabled=true`。
> 数值口径以 `AttributeDef.SHIELD_SCALING` 为准，本文描述公式与调参方式。

## 1. 公式

在 `UnitAttributes:recalc()` 末尾追加集中、可调、可回退的护盾成长层：

```
若 preGrowthES > 0:
    护盾 += 最终HP × hpRatio
          + 派生护盾 × ((1 + (等级-1) × derivedLevelFactor) - 1)
```

- **门控**：仅当单位成长前已有护盾（`preGrowthES > 0`）才追加，无盾敌人不会凭空获得护盾。
- 成长层结果不再被护盾加成二次放大。
- `enabled = false` 可一键关闭，数学上完全回退到不含成长层的公式。

## 2. 为什么需要成长层

护盾的三个数值来源（六围派生、装备词缀、敌人模板）均为线性或低阶增长，而 HP 与伤害随等级呈指数增长；中后期护盾占比因此塌陷，形同虚设。把护盾锚定到本身就指数增长的 HP 后，护盾在各等级段维持稳定占比。

## 3. 当前档位效果（裸装探针）

| 单位 | 无成长层 | 当前档（E） |
|------|---------|-----------|
| 敌人雷神 Lv345 | 护盾 821（占比≈0） | 约为最终 HP 的 8% |
| 战士 Lv200 | 占比 0.3% | 约 11.6% |
| 法师 Lv200 | 占比 2.8% | 约 23.6% |
| 牧师 Lv200 | 占比 4.8% | 约 31.2% |
| 无盾敌人 | 0 | 0（门控，不凭空加盾） |

> 实测绝对值随属性成长变化，以运行 `_proc/shield_probe.lua` 的输出为准。

## 4. 调参与验证

1. **只改 `AttributeDef.SHIELD_SCALING` 的两个数字**（`hpRatio` / `derivedLevelFactor`），其他代码不用动。
2. 改完跑 `_proc/shield_sweep.lua` 看全表 → `_proc/shield_ab_lab.lua` 看实战 A/B → `tests/shield_scaling_test.lua` 锁回归。
3. 彻底关闭成长层：`enabled = false`。

跑法（项目根）：

```bash
./.cli/UrhoXRuntime tests/shield_scaling_test.lua -tapcd_dir=. -tool_mode -graphicsheadless
./.cli/UrhoXRuntime _proc/shield_probe.lua         -tapcode_dir=. -tool_mode -graphicsheadless
```

## 5. 已知限制

- 护盾大数值（e15 量级）在 UI 上未加 K/M/B 缩写格式化。
