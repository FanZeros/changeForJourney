# 横屏三栏并行战斗改造方案（宿命旅途）

> 状态：规划稿 v1.0（2026-09-13）
> 前置调研：战斗系统现状分析见文末附录 A；本方案基于仓库源码 `scripts-src/` 逐文件核对。
> 已确认决策：三栏 = 三场**并行战斗**（每栏一支队伍）；战斗部分分辨率 = 设计参数可调；队伍用远征等级解锁。

---

## 1. 目标形态

总画布 **1920×1080（16:9）**，横屏三栏，每栏一场独立战斗：

```
+---------------------------- 1920 x 1080 (16:9) ----------------------------+
|  [栏1: 队1战斗]      [栏2: 队2战斗]      [栏3: 队3战斗]                      |
|                                                                            |
|   我4  vs  敌4        我4  vs  敌4        (未解锁: 锁+条件+编队入口)         |
|   左列竖排  右列竖排    左列竖排  右列竖排                                    |
|                                                                            |
|  各栏独立: HP/飘字/技能特效/胜负判定，互不干扰                                |
+----------------------------------------------------------------------------+
| 全局层: TopBar / 返回 / 速度切换 / 全局弹窗（现有全局弹窗协议不变）             |
+----------------------------------------------------------------------------+
```

- **栏1（队1）**：开局解锁，默认主战斗栏。
- **栏2（队2）/ 栏3（队3）**：达到远征等级阈值后解锁（阈值常量可配）。未解锁时该栏显示：锁图标 + 解锁条件 + 「去编队」按钮 + 该队当前配置预览。
- **战斗布阵**：由现状「上敌（CY=804）/下我（CY=1760）两横排 ≤5 卡」改为「**左 4 我方竖排 vs 右 4 敌方竖排**」，中央为弹道/特效区。
- **分辨率可调**：战斗区宽度、栏占比、卡片缩放全部收敛到一张设计参数表（§5），改常量即重新布局，页面代码零硬编码。

### 1.1 核心设计决策（已定，含理由）

| 决策点 | 结论 | 理由 / 影响 |
|---|---|---|
| 三栏内容 | 三场并行战斗，队伍↔栏 1:1 | 用户确认；"三个不同战斗要让其他地方正常运作" |
| 每队关卡进度 | **各队独立推进主线**（stage1/2/3 独立进度） | "三个不同战斗"成立的前提；数据上天然隔离；备选方案（共享进度三镜像）会导致"谁推进度"归属混乱，不采用 |
| 英雄唯一性 | **同一英雄同一时刻只能在一队** | 避免"三栏同一个神阵"把并行玩法变成三倍刷子；校验放服务端 `HeroService`，客户端 `CharacterPanel` 拖拽时同步提示 |
| 解锁方式 | 远征等级：队1=1、队2=10、队3=20（`TEAM_UNLOCK_LEVELS` 可配） | 复用现有 `ExpTable` 体系，与槽位解锁风格一致 |
| 每队人数 | 上限 4 人（槽位等级解锁 2→4，复用现有节奏） | 用户明确"左4角色vs右4敌人" |
| 奖励平衡 | 三场战斗各自掉落；队2/队3 独立从第 1 关爬，天然慢于队1；另留 `TEAM_REWARD_SCALE = {1, 1, 1}` 系数（默认不摊薄，后续可调） | 收益×3 风险由"独立爬塔"自然衰减兜底，系数表留调参余地 |
| 覆盖范围 | 本期只改**主线挂机战斗**为三栏；竞技场/副本/爬塔保持单战斗不变（Phase 4 完成后 `BattleView` 可低成本迁移） | 控制爆炸半径；四类战斗场景关系见附录 A |

### Phase 1 — 数据层：单队 → 三队（服务端权威）

**1a. 存档结构** `shared/heroes/HeroesSchema.lua`
```lua
-- 旧: heroes.deployed = {heroId, ...} (≤5)
-- 新: heroes.teams = {
--   [1] = { slots = {heroId|false, ...} },  -- ≤4
--   [2] = { slots = {...} },
--   [3] = { slots = {...} },
-- }
-- 兼容: 旧档 deployed 非空 → 迁入 teams[1]（超 4 人截断前 4），teams[2]/[3] 置空
```

**1b. 校验与业务** `server/hero/HeroService.lua`
- 上限校验 5 → `#slots ≤ 4` 且 `teamIdx ∈ 1..3 且 teamIdx ≤ getUnlockedTeamCount(level)`
- 新增跨队唯一性校验（同 heroId 只允许出现在一队）
- Handler 消息扩展：`DEPLOY_HEROES { teamIdx, slots }`

**1c. 解锁规则** `config/ExpTable.lua`
- 新增 `TEAM_UNLOCK_LEVELS = {10, 20}` + `getUnlockedTeamCount(level)`（队1 恒解锁）
- 复用现有 `getUnlockedSlotCount` 改造为每队 2→4 槽

**1d. 客户端编队 UI** `ui/CharacterPanel.lua` + `ui/CharacterPanelDraw2.lua`
- 单组 `teamSlots` → 三队页签（Tab1/2/3），未解锁页签置灰显示条件
- `getDeployedTeam()` → `getDeployedTeam(teamIdx)`；**所有调用点逐一适配**（`ui/DungeonPage.lua:1128/1163`、`ui/ArenaOpponentDialog.lua:592`、训练假人入口等）
- 竞技场/副本等入口本期固定用 `teamIdx=1`

**1e. 同步协议** `network/ClientMessageHandler.lua:224` 一带：推送结构由 `deployed` 改 `teams`

验收：旧档进入后队伍 1 完整保留；编队页可切换三队；等级 10 解锁队 2；LSP 零 Error。

### Phase 2 — 战斗核心：布阵左4vs右4 + 多实例化

**2a. 统一布阵模块**（新文件 `core/BattleLayout.lua`）
- 收编 `BattleDraw.lua:124-129` 与 `BattleCombat.lua:261-268` 两份重复公式为唯一实现
- 新布阵（全参数化，见 §5 参数表）：
```
栏内坐标（以栏为局部坐标系, 原点=栏左上）：
  我方卡 i (i=1..4): cx = ALLY_X,          cy = FIELD_TOP + (i-1)*(CARD_H*CARD_SCALE + GAP_Y)
  敌方卡 i:          cx = ENEMY_X,          cy 同上
  ALLY_X = 栏宽*0.28 ; ENEMY_X = 栏宽*0.72   （卡中心线）
```
- 射弹/近战动画、飘字、命中判定坐标全部走 `BattleLayout`，删除散落的常量副本

**2b. 战斗状态实例化**（重构 `ui/BattleCombat.lua`）
- 现状：模块级单例状态（单位表、时间轴、回调）→ 改为 `BattleCombat.newState(battleId)` 返回隔离状态表，API 从 `BattleCombat.xxx(...)` 变为 `BattleCombat.xxx(state, ...)`（保留旧签名薄包装过渡）
- `ui/BattleEffects.lua`、`ui/ProjectileSystem.lua` 同步按 `battleId` 分桶

**2c. 战斗视图组件化**（新文件 `ui/BattleView.lua`）
- 从 `ui/BattleScene.lua`（3257 行，构建已告警超长）抽出「渲染一场战斗 + 接收该栏输入」的 `BattleView`
- 接口：`BattleView.draw(vg, state, rect)`、`BattleView.hit(state, rect, dx, dy)`、`BattleView.update(state, dt)`
- `BattleScene.lua` 本身退化为「三栏页面的数据编排层」，顺带把行数压到阈值内

验收：单栏形态下（复用 `BattleView` 渲染一场）与现版本战斗表现一致；四类战斗入口回归通过。

### Phase 3 — 三栏并行战斗页

**3a. 设计参数表**（新文件 `config/BattleTriConfig.lua`，见 §5 全表）
- 栏宽 `COL_W=640`、战斗内缩放 `VIEW_SCALE`、卡片缩放等——**"战斗部分分辨率可调"的落点**

**3b. 三栏页面**（新文件 `ui/BattleTriPage.lua`）
```
draw:  for col=1..3: 栏背景 -> Viewport 式 begin(clip+scale) -> BattleView.draw(state[col]) -> finish
       locked 栏: 锁图标 + "等级 X 解锁" + 去编队按钮
update: 三场战斗各自 step（共享同一 timeStep，速度倍率可全局或按栏）
```

**3c. 主线进度改造**
- `BattleScene.loadStage` 按 `stage[teamIdx]` 取进度；推进判定按各栏独立胜负

**3d. 三处集成（铁律）**
- `network/Standalone.lua`：`HandleNanoVGRenderHorizon` 中 tab3 渲染替换为 `BattleTriPage`（替换现有"中面板塞 BattleScene"逻辑）；输入 `HorizonResolveMouse` 后按栏转发

验收：三场并行战斗同时推进、互不串扰；断线重连/重启后三队进度与三栏状态恢复正确；编队页在战斗进行中可正常编辑（编辑生效于下一场或按现有刷新协议）。

## 5. 设计参数表（分辨率可调的落点）

`config/BattleTriConfig.lua`：

| 参数 | 建议初值 | 说明 |
|---|---|---|
| `TOTAL_W / TOTAL_H` | 1920 / 1080 | 总画布（16:9 固定） |
| `COL_W` | 640 | 单栏宽度 = 战斗区宽度，**调它即调三栏占比** |
| `COL_GAP` | 0 | 栏间留白 |
| `VIEW_SCALE` | 1.0 | 战斗内容整体缩放（栏内再缩放，分辨率档位感来自这里） |
| `CARD_W / CARD_H` | 198 / 438 | 卡片原始尺寸（沿用现版） |
| `CARD_SCALE` | 0.5 | 卡片缩放（99×219，竖排 4 张 + 间距 ≈ 936px，适配 1080 高） |
| `GAP_Y` | 20 | 竖排卡间距 |
| `ALLY_X_RATIO / ENEMY_X_RATIO` | 0.28 / 0.72 | 我/敌列中心在栏宽中的比例 |
| `FIELD_TOP` | 72 | 战场顶留白（HP 条/栏标题） |
| `TEAM_UNLOCK_LEVELS` | {10, 20} | 队2/队3 解锁等级 |
| `TEAM_REWARD_SCALE` | {1.0, 1.0, 1.0} | 各队收益系数 |
| `RENDER_QUALITY` | "high" | 特效降级开关（low：非焦点栏关粒子） |

> 说明：数值均为首版建议值，全部可在一处表内调整重排；布局公式只读这张表。

## 附录 B — 前后排 × 技能树规划（Phase T1-T5）

> 2026-09-13 立项。受击权重已从指数公式（8/4/2/1）改为**权重表 5/4/2/2**
> （`BattleLayout.HIT_WEIGHTS`，1号位=前排/靠中心）。本节规划把前后排差异延伸进技能树。

### T0 现状基线

- 站位模型：每阵营 4 槽一列，**4 档连续站位**（1=前排/靠中心 → 4=后排），非硬性"前2后2"
- 受击权重：`BattleLayout.hitWeight(idx)` 查表 `HIT_WEIGHTS = {5,4,2,2}`；敌人选目标=威胁值×权重（ThreatManager）、治疗多目标反向偏后排（BattleCombat）
- 天赋生效方式：`TalentManager.applyBattleStartTalents(units, opposingUnits)` 战斗开始钩子 + 战斗中事件钩子（onAfterAttack/onEnemyDeath/onAllyDeath）；星图结构在 `shared/talent/TalentNodeDefs.lua`

### T1 站位查询 API（基础设施）

- `BattleLayout.rowIndexOf(group, idx)` → 1..4（1=前排/靠中心），替代各处散落的 `MAX_PER_SIDE - idx` 推算
- 战斗单位挂载时写入 `unit.slotIdx`（BattleScene/三行驱动 mount 处），战斗中换位自动刷新
- 死亡/替换链路保持 `slotIdx` 连续性（死亡即补位后新怪继承槽位）

### T2 天赋效果新原语（TalentEffect 扩展）

| 原语 | 结构 | 生效方式 |
|---|---|---|
| `ROW_STAT` | `{ rows = {1,2}, stat = AD.ARMOR, value = 0.12 }` | 战斗开始时按当前站位注入属性，换位重算 |
| `HIT_WEIGHT_MOD` | `{ rows = {1,2}, mult = 1.5 }` 或 `{ rows = {3,4}, mult = 0.5 }` | 实时修改自身 `hitWeight`（嘲讽/隐匿） |
| `ROW_TRIGGER` | `{ rows = {1}, event = "onHitTaken", ... }` | 站特定槽时的事件钩子（复用现有 TAL 钩子体系） |

- 注入点：`applyBattleStartTalents` 内遍历 `units` 时读取 `unit.slotIdx` 匹配 `rows`
- `HIT_WEIGHT_MOD` 聚合到 `BattleLayout.HIT_WEIGHTS` 的每单位覆写表（单位级，不污染全局表）

### T3 首批 8 个天赋节点（四系 × 前后排）

| 系 | 前排位（1-2 号位生效） | 后排位（3-4 号位生效） |
|---|---|---|
| 体魄 | **铁壁·阵**：受击权重 ×1.5（嘲讽），受伤 -12% | **圣徽·守**：站后排时全队受治疗 +15% |
| 刚力 | **刚猛·锋**：攻击 +18% | （刚力系无后排位）|
| 灵巧 | （灵巧系无前排位）| **瞄准·影**：暴击率 +8%，受击权重 ×0.5（隐匿）|
