## 4. H02：轮回过场的整体竖版 cover 损坏视口效果

### 证据与条件

- `scripts/boot/StandaloneBoot.lua:492-499` 在轮回回调实际启动 `IntroCutscene`，不是已删除的旧开场死模块。
- `scripts/ui/story/gate/IntroCutscene.lua:15-16` 缓存 `GameConfig.Design=1080×2400`；`:116-132` 以 DH/2 定位上下眼皮。
- `scripts/boot/StandaloneHorizon.lua:282-287` 把整个过场按 `max(1920/1080,1080/2400)` 放大裁切，而非仅裁切背景。
- `IntroCutscene.lua:744-759` 的内部 scissor 不撤销外层 cover；背景抖动单独 save/restore，不会抵消眼皮变换。

数学结果：scale=16/9，offsetY=-1593.333333，可见源坐标 Y=896.25..1503.75。openness=p 时，眼皮内缘映射为 `540−2133.333333p` 与 `540+2133.333333p`。因此 p≥0.253125 时眼皮已经没有可见遮挡面积。

阶段2 `IntroCutscene.lua:325` 的一秒 easeInOut 睁眼约在 **0.355756秒** 即全露出；p=0.25 时已露出画面高度98.765%。这是效果进度与实际可见遮挡不一致。

**措辞限制**：不把阶段3说成“大部分时间无遮挡”，它还有暗化/模糊；眼皮曲线仍连续，也不声称数学上的瞬间跳变。

### 待实施与验收

- [ ] 仅给 IntroCutscene 增加横屏视口尺寸；眼皮、黑底、暗角和字幕按视口布局。
- [ ] 背景图片单独 cover，取消对整个过场的竖版 cover；不全局修改 GameConfig.Design。
- [ ] 保留原阶段时长、音效、轮回完成回调与字幕内容。
- [ ] 验收p=0/0.25/0.5/0.75/1对应的遮挡，五阶段字幕及眼皮都留在内容帧内；轮回完成只回调一次。

## 7. H05：塔内功绩奖励的特定归属输入错位与滚轮下放

### H05a：left note与旧分栏不一致

条件必须同时满足：塔运行、功绩页打开、三行页已关闭、非row奖励归属为left。

- `scripts/boot/Standalone.lua:1011-1013` 在塔运行时关闭主线三行页。
- `scripts/boot/StandaloneHorizon.lua:709-712` 把塔内功绩left note改为X=0..486；同文件`:97-119,734`按此note绘制归属奖励。
- `scripts/boot/StandaloneHorizonInput.lua:143-161` 在tri=false时仍用 `Viewport.hit(H_ox,H_oy,H_s)` 分类；正常旧三栏left范围为X=231..717。
- 奖励至少六项且入场动画已结束时，`RewardPopup.lua:450-458` 的layoutScale=1，网格设计矩形X=71..1009、Y=838..1178，实际为X=31.95..454.05、Y=377.1..530.1。
- 在可见网格 `(100,450)` 按下却判为rp_out，不开始奖励拖拽；`:1028-1030`释放直接关闭。奖励超过两行（>10项）时，该处本应允许滚动，却滚不到。

**归属限制**：塔功绩输入 `StandaloneHorizonInput.lua:167-171` 返回left但不写H_focusPanel；`ClientMessageHandler.lua:474-479`任务/功绩奖励不传panel，`RewardPopup.lua:540-541`沿用旧焦点。因此不是每次塔内领奖都left；旧焦点为left或显式指定left才满足此错位条件。

普通轻点本来就可关奖励，不把“rp_out关闭”单独夸大为不能领奖。功绩奖励通常无onItemClick且非cascade，不用假设未启用的回调来夸大影响。center/right在固定1920帧正常塔状态下没有确认相同错位。

### H05b：非row奖励滚轮穿透与中心幽灵命中

- `StandaloneHorizonInput.lua:1384-1409`只有hitPanel成功才return，否则继续派发下层。
- 塔功绩覆盖时会落到`:1412-1414`滚动TaskPage。即使奖励属center，在其卡外滚轮仍可操作下层功绩。
- 上述left/layoutScale=1状态中，`(100,450)`位于真实网格，旧分栏判定失败；中心兜底逆变换也不命中，随后滚下层TaskPage。
- 反过来 `(900,450)`不在实际left奖励，`:1403-1408`却用center letterbox换算为 `(406.666667,1000)`，hitPanel成立，错误派发left奖励滚轮。
- 网格算例均以入场动画结束为前提；错误派发不依赖奖励条数，但观察奖励列表实际位移需>10项，观察下层TaskPage实际位移需其列表有滚动余量。没有余量时不声称偏移一定变化。
