## 0. 结论（先看这个）

当前每位英雄 **4 槽**：`weapon / offhand / armor / accessory`（主手、副手、护甲、饰品）。

目标变为 **6 槽**：

| 槽 key | 中文 | 是否已有模板 | 职业限制 | 强化卷轴 |
|--------|------|--------------|----------|----------|
| `weapon` | 主手 | 有（72） | `HeroConfig.weaponTypes` | `weaponScroll` |
| `offhand` | 副手 | 有（30） | `HeroConfig.offhandTypes` + 双手占用 | `offhandScroll` |
| `armor` | 护甲（胸甲） | 有（60） | `ClassConfig.armorTypes` | `armorScroll` |
| **`helmet`** | **头盔** | **无，需新建** | **同胸甲：跟职业护甲类型** | **`helmetScroll`（新建）** |
| **`shoes`** | **鞋子** | **无，需新建** | **同胸甲：跟职业护甲类型** | **`shoesScroll`（新建）** |
| `accessory` | 饰品 | 有（36，戒指/项链/耳环仍共用 1 槽） | 无限制 | `accessoryScroll` |

**不改协议动作名**（`equip_item` 的 `slot` 本来就是字符串）。旧存档向前兼容：缺的槽视为空。

## 1. 现状（代码已核实）

### 1.1 数据模型

穿戴存在 `equipment.equipped[heroId][slot] = seq`，槽名是自由字符串，**加 key 不会炸旧档**。

槽位强化存在 `slotEnhance.levels[partySlot][equipSlot] = lv`，缺 key = 0 级，同样兼容。

唯一真相源本应是 `EquipmentConfig.SLOTS`，但下面这些地方把 4 槽写死了，必须一起改：

```
EquipmentConfig.SLOTS
BlacksmithPage.EQUIP_SLOT_ORDER
CharacterDetailDraw.DT_SLOTS
EquipmentBag.FILTER_TABS
DebugPanel.EQUIP_SLOTS
EquipmentService.EquipAllBest 的 SLOT_ORDER
DropSystem.SCROLL_TYPES
MarketService.SCROLL_TYPES
BlacksmithConfig.SLOT_SCROLL_MAP
```

属性汇总（`CharacterPanel` / `CharacterDetailAttrs`）已经 `ipairs(EquipmentConfig.SLOTS)`，**改 SLOTS 就会自动吃到新槽**。

### 1.2 护甲类型（头盔/鞋子要复用）

`ClassConfig.armorTypes` 用的是枚举 → 中文名：

| 职业 | 可穿 |
|------|------|
| 守誓者 | 板甲、重甲 |
| 破阵者 | 重甲 |
| 咒术师 | 布甲、轻甲 |
| 夜猎者 | 轻甲、皮甲 |
| 无痕者 | 皮甲 |
| 提灯者 | 布甲、皮甲 |

胸甲模板的 `type` 就是 `"皮甲"/"轻甲"/"重甲"/"板甲"/"布甲"`。

**头盔、鞋子的 `type` 继续用这 5 个中文名**，不要新发明「皮盔/布帽」枚举。槽靠 `slot` 区分，职业限制靠现成 `armorTypes`，`ClassConfig` / `AttributeDef` 不用加枚举。

### 1.3 掉落

`EquipmentSystem.generateRandom` = 在 `SLOTS` 里均匀抽槽，再 `generateBySlot`。  
`DropSystem.rollScrollDrop` = 在 4 种卷轴里均匀抽。  
市场「随机卷轴」同理。

### 1.4 UI 槽位坐标（角色详情）——现状是 2×2 长方形

立绘卡片：中心 `(540, 497)`，尺寸 **198×438**。槽 160×160。

现有 4 槽（长方形四角）：

```
护甲 (259, 382)          饰品 (810, 382)
主手 (259, 592)          副手 (810, 592)
```

水平半距 ≈ 281px，垂直半距 ≈ 105px。槽与卡边缘几乎贴齐，没有第三行的空间——所以 6 槽不能再做成 2 列×3 行的「更高长方形」（会压到名字/标题，也会挡住脸）。

铁匠铺一行 4 槽：首槽 X=227，尺寸 160，间距 49 → 末槽中心 854，刚好塞进 1080 宽。**6 个横排会挤爆**，铁匠仍改 2 行×3 槽（铁匠没有立绘，不必六边形）。

装备图标路径：`image/装备图标/UI_icon_ZB_{templateId}.png`（如 `UI_icon_ZB_A1.png`）。  
胸甲目前是「一组 6 阶共用一张」的稀疏落盘（A1/A7/A13…），不是每件一张。头盔/鞋子按同样规则做。

## 2. 为什么头盔+鞋子比拆饰品「更完善」

拆饰品（戒指/项链/耳环）模板已在，改动小，但玩法上只是把 1 个饰品槽切成 3 个，防御向成长几乎不加。

头盔+鞋子：

- 补齐 ARPG 身体部位（头 / 胸 / 脚），和现有胸甲职业限制同一套逻辑。
- 给防御向（HP/护甲/盾）和机动向（攻速/闪避/命中）单独出口，不只堆饰品词缀。
- 代价：模板、图标、卷轴、UI 布局、掉落权重、战力都要新建。下面按这个代价写全。

双手武器占用副手的规则 **不动**。新槽与双手无关。

## 3. 设计拍板（实现时按此，不要临时改口径）

### 3.1 槽位 key / 前缀 / 中文

| key | 中文（UI） | 模板 ID 前缀 | 空槽图后缀建议 |
|-----|------------|--------------|----------------|
| `helmet` | 头盔 | `H`（H1…） | `TK`（头盔） |
| `shoes` | 鞋子 | `S`（S1…） | `XZ`（鞋子） |

`EquipmentConfig.SLOT_NAME`、`SLOT_PREFIX`、`slotCounter` 同步加这两项。

### 3.2 模板体量

对齐胸甲结构，而不是缩水成「每种 1 条」：

- 5 护甲类型 × 2 变体 × 6 等级段 = **每槽 60 件**
- 头盔 60 + 鞋子 60 = **+120 件**
- 装备总数 198 → **318**

等级段与胸甲完全一致：`{1,16} {17,32} {33,48} {49,64} {65,80} {81,9999}`。

`type` 字段仍写 `"皮甲"` 等，穿戴校验直接复用胸甲那套 `AD.ARMOR_TYPE_NAME`。

### 3.3 数值角色（旧件下调 + 新件补位，避免 6 槽把战力抬翻）

**拍板：旧 4 槽模板基础属性整体下调，给头盔/鞋子腾预算。**

原因：若胸甲/武器维持现状，再加头+鞋，全套战力会涨一截。用户要求「其他部件属性稍微调低」，目标是 **6 槽满穿战力 ≈ 现在 4 槽满穿的 100%~108%**，体感「部位变多、单件变薄」，不是「穿 6 件突然变强」。

#### 3.3.1 旧模板下调（`EquipmentConfig.ITEMS` 里 `v = {...}`）

| 槽 | 下调 | 说明 |
|----|------|------|
| 武器 `weapon` | 主属性 × **0.88**，次属性 × **0.90** | 输出核心，少削一点 |
| 副手 `offhand` | 全部 × **0.88** | 盾/法器跟着走 |
| 护甲 `armor` | 全部 × **0.85** | 防具三件（胸/头/鞋）要分预算 |
| 饰品 `accessory` | 全部 × **0.90** | 饰品仍是唯一无职业限制槽，少削 |

实现：对 `addGroup` / `addItem` 的 `v` 数组逐项乘系数后四舍五入到现有精度（HP 取整，百分比留 1 位）。**不要**在运行时乘全局系数——改模板数字，hydrate 会重算。

`hydrate()` 在缺 `baseStats` 时按模板重算；`dehydrate()` **不持久化 baseStats**。所以：
- 旧档装备下次加载会自动变成新数字（无需迁移函数）
- 词缀 `affixes[].value` 是生成时 roll 的，**不动词缀**（用户说的是部件基础属性）
- 强化等级、品质倍率公式不改，仍叠在新基础值上

#### 3.3.2 头盔 / 鞋子（相对「下调后的胸甲」）

下调后 1 级段胸甲 `maxHp` 约 `119 × 0.85 ≈ 101`。头盔/鞋子不要再抄这个数。

| 槽 | 主属性 | 次属性 | 相对下调后胸甲战力 |
|----|--------|--------|--------------------|
| 护甲（胸） | `maxHp`（已 ×0.85） | 维持现有次属性种类 | 100%（新基准 P'） |
| 头盔 A | `hitValue` | 小 `maxHp`（胸甲的 ~30%） | ≈ 0.38 P' |
| 头盔 B | `energyShield` / `armor` | `int`/`spi` 或 `esBonus`（布甲线） | ≈ 0.38 P' |
| **鞋子 A（攻速）** | **`atkSpeed`** | 小 `maxHp` 或 `agi` | ≈ 0.42 P' |
| **鞋子 B（闪避）** | **`dodge`** | 小 `maxHp` 或 `agi` | ≈ 0.42 P' |

鞋子 A/B 都做（已拍板）。`atkSpeed` 1 级段对齐现有单手剑次属性量级（约 **1.6%~1.8%**，下调后武器次属性还会再 ×0.90，鞋子攻速不要超过下调后的单手剑次属性）。

合计：头+鞋 ≈ **0.80 P'**。加上旧 4 槽 ×0.85~0.90 之后，6 件总战力约等于现在的 4 件。

开工前用一张对照表（无词缀、品质 1、1 级段）验算：

```
旧 4 件合计战力  Q0
新 6 件合计战力  Q1
目标  Q1 / Q0  ∈ [1.00, 1.08]
```

### 3.4 职业限制

头盔、鞋子 **与胸甲同一套** `classCfg.armorTypes`：

- 咒术师不能穿板甲头盔/板甲靴
- 无痕者只能皮
- 饰品仍不限制

一键装备、背包红点、详情「可提升」判断，三处都要给 `helmet`/`shoes` 走 armor 分支（现在只有 `slotName == "armor"`）。

建议抽一个函数，避免 4 处复制：

```lua
function EquipmentSystem.getWearableTypeSet(heroId, slotName) --> { [typeName]=true } | nil
```

`nil` = 不限制（饰品）。

### 3.5 掉落权重

`generateRandom` 现在 4 槽均匀 → 改 6 槽均匀后，胸甲/武器出现率从 25% 降到 16.7%。

**第一版就均匀 6 槽**（实现简单、玩家能刷到新部位）。若实装后武器/胸甲太稀，再改加权（例如 weapon 2 / armor 2 / 其余 1）。不要第一版就上复杂权重。

### 3.6 卷轴（必须新建，禁止和胸甲共用）

若头盔/鞋子也吃 `armorScroll`，铁匠 3 个防具槽抢同一种卷轴，强化节奏会烂。

新建：

| 货币字段（camelCase） | 奖励 type（snake） | 中文 | 图标 |
|----------------------|--------------------|------|------|
| `helmetScroll` | `helmet_scroll` | 头盔卷轴 | `UI_icon_JZ_TK.png`（新建） |
| `shoesScroll` | `shoes_scroll` | 鞋子卷轴 | `UI_icon_JZ_XZ.png`（新建） |

强化消耗表 `ENHANCE_TABLE` **不改**（每槽独立 100 级，金币/卷轴数沿用）。玩家要养 6 条强化，总消耗自然变高，这是 6 槽的代价，不在第一版给折扣。

随机卷轴池：4 → 6 种均匀。市场「随机卷轴」商品不用改价，只是池子变大。

`ResourceDefs.ID_TO_TYPE` 追加新序号（建议 `"24"`/`"25"`，避开已用 1–23）。旧邮件/奖励字符串不会引用新 ID，安全。

### 3.7 双手 / 双持

完全不碰。新槽没有 grip，不进 `applyEquip` 的 offhand 特例。

`EquipAllBest` 处理顺序改为：

```
weapon → armor → helmet → shoes → accessory → offhand
```

武器仍先于副手，双手互斥逻辑保持。

## 4. UI 布局

### 4.1 角色详情：正六边形围立绘（已拍板，替代 2×3 长方形）

立绘卡片 198×438，中心 `(540, 497)`。槽 160×160，选中底 234×234。

几何：6 个槽绕中心均匀分布，相邻夹角 60°。半径取 **R = 248**（槽中心到立绘中心），保证槽外接圆不相交（最小中心距 = 160+16 边距 = 176；R×1 = 248 > 176）。

顶点朝上（头盔在正上方、鞋子在正下方），左右 4 槽贴近现有 X=259 / 810：

```
                    头盔 (540, 249)
           护甲 (325, 373)          饰品 (755, 373)
           主手 (325, 621)          副手 (755, 621)
                    鞋子 (540, 745)
```

计算（cx = 540 + R·sinθ，cy = 497 − R·cosθ，θ 从正上方顺时针，Y 向下所以减 cos）：

| 槽 | θ | cx | cy | 身体对应 |
|----|---|----|----|----------|
| helmet | 0° | 540 | 249 | 头 |
| accessory | 60° | 755 | 373 | 右上（饰） |
| offhand | 120° | 755 | 621 | 右下（副手） |
| shoes | 180° | 540 | 745 | 脚 |
| weapon | 240° | 325 | 621 | 左下（主手） |
| armor | 300° | 325 | 373 | 左上（胸） |

**为什么可行**
- 现有左右 X=259/810 是更「扁」的矩形。六边形把左右收到 325/755（+66px 向内），给立绘让出水平空间，避免 160 槽切进卡片。
- 头顶 cy=249：上半背景顶约 477−1290/2 = −168（被 scissor 到 0），槽上沿 249−80=169，**不贴顶**。
- 脚下 cy=745：名字在卡底 `497+253=750` 附近，**会和鞋子槽重叠**。P2 必须把名字/经验条下移或改到卡右侧，不能让鞋子盖字。备选：R 收到 230，鞋子 cy=727，仍可能擦到名字，优先移名字。

`DT_SLOTS` 按视觉顺时针写，`handleInput` 已 `ipairs`：

```lua
{ helmet, accessory, offhand, shoes, weapon, armor }
```

绘制分支按 `slot` 显式匹配，禁止 `else = 饰品`。双手占用副手的镜像逻辑仍只作用在 `offhand`。

P2 预览检查清单：
1. 六槽不相交、不切出 1080 宽（最右 755+117=872，OK）
2. 不挡脸、职业标
3. 鞋子不盖角色名 / 经验条（必要时下移 MID_NAME 或 NAME_BG）
4. 选中底 234 不和其他槽叠成一团

## 7. 平衡与掉落（上线前必做的表）

对照表（无词缀、品质 1、1 级段）必须同时满足两条：

```
头+鞋  ≈  0.80 × 下调后胸甲战力 P'
6 件合计 Q1  /  旧 4 件合计 Q0  ∈ [1.00, 1.08]
```

鞋子 A 攻速 1 级段 ≤ 下调后单手剑 `atkSpeed` 次属性（约 1.6%），禁止抄胸甲 HP。

掉落体验：

- 击杀掉落仍「先 roll 是否掉，再 `generateRandom`」。
- 6 槽均匀后，刷齐一套更慢，这是预期。
- 首通 `fcMinQ` 装备件数若按件给，会按新 SLOTS 随机，可能首通直接出头盔——可以接受。

强化：6 条 100 级，金币总消耗约 ×1.5。第一版不打折，若后期觉得铁匠太坑，再给「防具三件共享折扣」也不迟。
