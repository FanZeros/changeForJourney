# 远征升级提示与奖励页规划（2026-10-03）

## 范围与结论

用户要求排查远征升级提示白图，并规划升级领取黑钻等与展示解锁内容的页面。本轮以 `workspace930@8d3e62f` 只读分析和真实离屏复现，不实施经济奖励或擅自移除升级效果；PR24冲突修复在独立分支完成，未混入本方案。

推荐复用现有 **城镇功绩 → 远征页签**。增加 **玩家信息的等级/经验区直达入口**，升级弹窗只做庆祝和奖励摘要，不承担永久领取台账。游戏“黑钻”当前是奖励类型 `diamond`、存档 `currency.gems`、界面名称“黑晶”，无需新增货币。

## 1. 白图证据与最小处理建议

### 已确认

- `scripts/ui/hud/popup/LevelUpPopup.lua:37` 实际加载 `image/spine/UI_SPINE_DJTS.json`，不是旧箭头图片。
- `init()` 只缓存上下文，`show()` 仅在已加载时启动动画，首次 `draw()` 才加载；加载成功后没有 pending-animation 补播。`preload()` 当前无外部调用者。
- 该模块设置 PMA=false，而 `assets/image/spine/UI_SPINE_DJTS.atlas` 标注 `pma:true`。
- atlas标注2465×2465，实际PNG为2048×2048，区域仍按原尺寸；这属于资源不匹配，不能只改size而不重算全部region/offset/骨架尺寸。
- Spine含白色横条、圆环、符纹与additive层；入场前0.3秒不绘制卡片，背景和光效独自显示。卡片alpha230，解锁行白底alpha28。

### 本轮真实复现

临时NanoVG入口调用真实 `LevelUpPopup.init/show/update/draw`，设计空间1080×2400、实际960×540；控制动画时间，以cold/warm/PMA/both对照。

- 冷首次展示0/0.2秒出现灰白渐变矩形，停留setup pose；日志为先show后Spine加载，没有启动对应动画。
- 预加载后0.2秒出现明显白色横条；0.8/1.8秒卡片仍可透出中央窄背景。
- PMA=true对照不会自动消除这些白色形状；不能宣称“只改PMA就修好”。
- 四组0.8秒渲染报告均135帧原始PASS、Lua/资源/引擎错误0；说明异常不是资源文件缺失，视觉问题仍存在。后续0/0.2/1.8秒截图已实查。
- 临时入口及meta已删除、官方重建成功，不提交验收截图或临时脚本。

### 建议让用户选择

**推荐：移除旧竖版升级Spine背景，改为当前暗金横向卡片＋轻量程序化光晕。** 保留标题、等级、远征点提示和解锁列表、原点击/自动关闭节奏；不需要生成素材或修复这套错尺寸图集，也不会再出现setup矩形与白横条。此为风格/效果变化，需用户确认后在新修复分支实施，不扩展移除其它战力Spine。

若用户希望保留原动画：先恢复图集尺寸一致（优先原始正确PNG/atlas，不仅改两数字），对齐PMA，再补pending animation，完成冷首次/再次播放/关闭/重开与多个时间点验收。代价更大，且白色横条可能本来就是原设计，需要明确是否删除该元素。

`SpinePowerUpEffect` 的短暂白焰属于另外一个 `PLAYER_POWER_CHANGED` 效果，图集/PMA匹配，不能把其白焰顺带当升级白图删除。

## 2. 推荐入口与页面

### 常驻入口

1. 城镇 **功绩 → 远征**：现有等级功绩及单领/一键领均在，优先改这里。
2. 玩家信息等级/经验区加“远征奖励”按钮，直达同一页签；应在该面板未命中即关闭分支前消费按钮。
3. 功绩建筑红点复用，等级区可提示“可领N项”；不要与新头像红点混用。
4. 升级弹窗加“查看奖励”入口和本次升级摘要；跨多级合并成一条提示，不连弹或覆盖前一级解锁。

### 远征页内容

- 顶部：当前远征等级、经验进度、下一里程碑、可领取数量。
- 中部：按等级排列的滚动奖励行，优先定位当前可领取项。
- 每行：`Lv.N / 黑晶×数值＋辅助资源 / 真正解锁说明 / 未达成·领取·已领取`。
- 底部或标题旁：一键领取当前页所有已达成未领项；未达成可预览，已领取保留历史状态。
- 解锁说明单独区分 **等级解锁** 与 **通关解锁**，不因高等级误写队伍已开放。

- Lv1每队3人，Lv2每队4人；Lv6/Lv10旧“出战槽位+1”文案已被4人上限截断，不能继续当实际新增解锁。
- 装备强化上限随远征等级增长。
- 神器第1格Lv30、第2格Lv60，读取 `ArtifactSchema` 真源。
- 教堂正式Lv30开放、引导期豁免；古树当前仅引导门控，不能误写同样Lv30。
- 小队2/3按普通9-5/19-5通关，不属于等级奖励。
- 远征点由等级决定上限，礼包领取不再加一份。

推荐结构化配置保存条件type/value与展示名称，UI、规则和弹窗读取同源，避免通过中文unlockName推断规则。

## 5. 接入前的必要修补顺序

### 先统一等级数据

当前战斗 `GameState.addExp()` 更新本地state并发事件，但等级功绩读PDM.player、顶栏优先cachedLevel；本地桥只同步货币。规则层离线/GM升等级反向syncPlayerData不发升级事件。静态接线缺口已确认，具体玩家症状尚未本轮跑数据复现。

新页前先用测试复现并统一 **数据提交 → 模块通知 → from/to等级事件**，覆盖战斗/扫荡/离线/GM、跨级、重启。不能只让UI显示新等级而领取校验读旧值，也不能直接启用旧多人代理模式。

### 再保证发奖与台账可靠

复用 `GameAction → LocalActionBridge → TaskHandler/TaskService → CurrencyService → PDM/Dispatcher → StandaloneSave`。

- 永久 `task.achClaimed` 已存在，可复用稳定 `a_plv_N` ID。
- `TaskCompat`不清永久领取表；新增未领项可补领，已有已领记录必须保留。
- 已领奖励内容改了要不要补差额应单独确认；不能清空台账让旧礼包重领。需要差额时用版本化一次性补偿记录。
- 当前ClaimTask先标已领再发奖、未检查发奖成功。新增等级奖励应预校验所有物品，奖励与台账同批提交；失败不标已领。
- `PDM.FlushImmediate()`只是日志，实际文件落盘为 `StandaloneSave.Flush()`；重要领取应确认真实保存成功及失败反馈。
- RewardPopup只展示成功回包，不负责发货。

## 6. 验收清单与范围

- 升级白图：冷首次/第二次/跨级重开、入场0/0.2/0.8/1.8秒、点击/自动关闭、横屏letterbox与DPR、其他战力光效未误删。
- 等级同步：战斗/扫荡/离线/GM统一新等级；顶栏、任务校验、点数上限一致。
- 发奖：单领/一键领、重复点击、重新开页与重启不重领、写档失败不虚报成功、无有效奖励定义不改台账。
- 老档：达到高等级未领取可补领；已领取记录保留；差额补偿最多一次。
- 解锁：Lv2满4槽；Lv30/60神器；等级未满足/关卡未通不能显示已开放，小队不跟等级错误开放。
- 不新建货币，不联网改造，不生成素材，不调角色战斗平衡；奖励数值与白图效果方案待用户选择。
